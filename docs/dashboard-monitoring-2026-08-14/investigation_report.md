# Server Desk 监控首页改版调查与实现报告

## 目标

1. 按参考图重构 Server Desk 首页视觉语言。
2. 结合 One人事官网当前配色建立统一设计变量。
3. 为每台有效服务器提供活性、资源、IO、空间和月度套餐流量监视块。
4. 保持服务器资产、环境体检、审计和设置功能可继续使用。

## 调查证据

| 主题 | 证据 | 结论 |
| --- | --- | --- |
| One人事当前配色 | 2026 年 8 月 14 日读取 `https://onehr.jp/` 的页面计算样式 | 背景 `#f7f8fa`，正文 `#333333`，主橙色约 `#fc6d26`，辅助青色 `#00c4cc` |
| 参考图布局 | 用户提供的面板截图 | 白色侧栏、浅灰工作区、圆角白卡、轻边框、高留白、橙色主操作 |
| 现有机器数据 | `mesh_health_samples.details_json.self` | 已有负载、内存和磁盘占比，可扩展累计计数后计算实时速率 |
| 现有面板资料 | 生产资料库只读检查 | 三台服务器保存的是 1Panel 地址，供应商套餐后台资料没有统一字段 |
| 供应商会话 | 隔离浏览器与可用浏览器列表检查 | 当前没有可用的供应商后台登录会话，无法取得 2026 年 8 月 14 日的在线套餐读数 |

## 数据边界

机器侧心跳负责活性、CPU、内存、文件系统空间、网卡计数和磁盘计数。供应商侧读数负责套餐已用流量、套餐限额和计费周期。两类数据具有不同证据来源，因此分别采集和保存。

套餐流量只使用 `server_subscription_usage` 保存的供应商管理画面或官方 API 读数。每条读数都绑定服务器、实际周期起止日期、已用量、限额、来源和采集时间。不同服务器的周期彼此独立。Agent 网卡计数只用于实时网络 IO。

2026 年 8 月 14 日的生产诊断确认，原自动账本在 02:28 UTC 初始化，首次质疑时只运行约六分钟。两台 Gate 显示 MB 是短采样区间的网卡增量，页面把它放进套餐区域后容易被理解为整段账期用量。该数据来源与供应商计费口径不同，已从套餐数据链路中移除。

## 供应商接口调查

| 供应商 | 当前可用机制 | 结论 |
| --- | --- | --- |
| AWS | CloudWatch `NetworkIn` 与 `NetworkOut` 字节指标 | 有正式 API。当前 Agent 指标可覆盖相同实例流量，AWS 没有固定套餐限额时占比需要用户定义预算 |
| Sakura VPS | 官方 API v7 | API 支持服务器状态和操作，当前文档没有 traffic、transfer 或通信量端点 |
| VMISS | `app.vmiss.com` 客户后台 | 后台显示套餐流量，官方条款限制自动设备或流程监控网站，页面爬取不作为常驻方案 |
| OrangeVPS | WHMCS 客户后台 | 官方知识库确认流量套餐和附加流量，公开资料没有客户流量 API，自动接口证据缺失 |
| Riven Cloud | 供应商控制台 | 截图确认控制台提供用量、限额和计费周期，公开 API 证据缺失 |
| CCNode、CNDRP | 供应商资料不足 | 公开 API 和正式后台接口证据缺失 |

供应商流量接入按证据能力分级。具有正式流量 API 的供应商使用专用适配器。缺少正式 API 的供应商需要经过授权的后台会话和逐站验证。当前没有可复用的供应商登录会话，因此生产首页保持等待供应商读数状态。VMISS 的自动化还需要先确认其条款允许的方式。

## 实现

### 数据库

新增 `schema_migrations`。版本 1 创建 `server_subscription_usage`，唯一键为服务器、周期开始和周期结束。重复录入同一周期会更新读数并刷新采集时间。

版本 2 曾创建 Agent 套餐账本。数据目标复核后确认网卡增量不应代替供应商账单用量。版本 3 以幂等迁移清空错误口径数据，运行代码停止读写该账本。表结构在发布观察期内保留，满足上一版本的短期回滚安全，稳定后通过独立迁移删除。已经部署的版本 2 迁移历史保持不变。

版本 4 创建 `server_provider_access`。每台服务器保存供应商后台地址、管理用户、加密密码、供应商服务编号、外部服务器标识、连接器类型、同步开关和最近同步状态。密码不进入服务器列表、首页接口、文档或截图。

### 心跳 Agent

Agent 版本更新为 2.1.0，新增以下累计值：

* CPU 总时间与空闲时间
* 默认路由网卡接收与发送字节
* 物理磁盘读取与写入字节
* 根分区总容量与可用容量

管理端从最近十二个采样周期中选择两个节点观测时间不同的可信样本，按时间差计算 CPU 使用率和每秒 IO。相同心跳负载可能被邻居传播到连续周期，聚合器会跳过重复的 `observed_at`。计数器回绕、时间差无效和只有一个独立观测时返回空值，界面显示“等待样本”。

心跳网卡计数继续计算每秒上下行速率，供运行状态和异常诊断使用。该计数不会写入供应商套餐表。

### 首页接口

`GET /api/dashboard` 返回所有有效服务器的卡片数据与汇总。活性状态使用当前样本年龄和分布式心跳确认结果。`PUT /api/servers/{id}/subscription-usage` 保存供应商月度流量并记录审计。

保存供应商读数时只更新对应服务器和对应账期的权威快照。页面不会在该读数上叠加 Agent 网卡增量。

Riven Cloud 连接器通过 `portal.sa.net` 客户区登录，调用 VirtFusion Direct 的 `loginAsServerOwner` 单点登录，再从 `cloud.sa.net/server/{内部编号}/resource/traffic.json` 读取 `monthlyRaw`。连接器校验固定域名、数字服务编号、UUID 服务器标识、当前周期和返回结构。后台默认每 6 小时运行，连接页同时提供立即同步入口。失败状态和安全截断后的错误原因写入供应商档案。

### 界面

监控首页成为默认页签。服务器资产改为独立页签。每个服务器卡片包含：

* 活性状态和最新样本时间
* CPU、内存和系统盘占比
* 网络上下行与磁盘读写实时速率
* 根分区可用与总容量
* 供应商套餐已用量、限额、占比、独立周期、来源和采集时间

## 当前数据状态

生产服务器的套餐后台登录资料尚未进入 Server Desk，当前浏览器没有可复用的供应商后台会话。七台服务器的 Agent 继续提供运行侧 IO，套餐区域不再展示 Agent 推算值。取得每家供应商授权访问资料后，需要逐台建立服务编号映射，并验证实际账期、已用量、限额和取数频率。
